# Tidebreak v0.5 · 玩家行为驱动的海岛冒险

这次重构的目标是改变玩家做决定的方式，而不是继续增加同一套弹幕的数量。v0.4 的主要问题是：所有首领都能用“射发光靶、等统一输出窗口”处理；岛屿虽然换了场景与任务，探索、学习和战斗之间的因果仍不够清楚。本轮以“探索学会一个新动作，在首领战中运用它，带着新用途继续航行”为全流程骨架。

以下区分已实现的规则与仍需真人验证的体验目标。自动化测试只能证明输入、状态与恢复流程，不能证明游戏已经达到商业发行质量。

## 一次航行的节奏

1. **抵岛先看见异常。** 远处有能辨认的地标、当地人的困境和本岛危险的现场痕迹；任务说明给出行动理由与具体下一步。介绍只传达一项新信息，不一次列完整系统。
2. **先低压学习，再带压力应用。** 普通探索和本岛任务负责教会该岛的新动作。首领会把这个动作放进时间、空间或资源压力下，不能成为与前面调查完全无关的考试。
3. **战斗和收益互相连接。** 普通捕鱼提供基础金币、熟悉武器与鱼类攻击；精英提供风险更高的鱼获与观察价值；首领不是刷钱捷径，而是航线与叙事的转折。
4. **金币必须带来下一次选择。** 航行中的装备、钓具和专精都通过金币购买。不同流派改变操作或输出条件；同层互斥选择、明确上限和不同适用场景，优于无限叠加全局伤害。
5. **离岛前有回响。** NPC、环境或日志应解释刚才的行动改变了什么，并留下下一岛的具体线索。不能只显示“已完成，去下一关”。

现有九岛任务已各自采用供能防守、回应旋律、护送净水舟、三轴星盘、黑匣下载、解冻救生舱、限时送电、双阀锻造和逆潮封锚。本轮首领机制与这些地区的知识主题关联；第一岛巨蟹以引导与躲闪建立读预警习惯。这不等于十一种操作都已有独立的无伤实操教程：例如三轴星盘与转镜、黑匣下载与钟拍的联系目前主要依靠角色提示，首次接触的理解成本仍要检查。后续内容增补应优先完善抵岛观察和离岛反馈，而不是再添加一轮相同的交付清单。

## 可读性与公平约束

- 每个场景对象都有物理含义：木桩、声贝、泵、污染环、反光镜、悬钟、热炉、线圈、接地网格、阀门、足迹晶体、触腕和声呐盘。声呐台底座有窄碰撞体，防止玩家走进盘面遮住观察视线；其他机关保持可穿行，恢复路线留有足够空间。
- HUD 的 `Cue` 负责当前状态、进度、倒计时及动作；`TargetPoint / TargetLabel` 负责导向。危险不能只靠颜色表达：锁定、绿区时机、红潮松手、双环 / 单环都同时给出文字或形状信号。
- 音鳐提供完整文字乐谱；白鲸第一阶段给出方位，后两阶段只保留可观察的双环 / 单环形状和西 / 中 / 东实体观测点，不提前标出正确答案。听力、音量和色觉不应成为通关前提，图形辨认仍须在实机画面中验证。
- 所有机制使用初始装备、E、移动、冲刺 / 跳跃。没有付费武器、鱼饵、炸弹、声呐消耗品的硬要求。
- 允许机制期间的条件减甲，但健康边界保留：第一、二阶段不能被爆发跨过；第三阶段未完成机制时至少保留 1 HP。禁止通过纯输出跳过教学动作。
- 不用失败后全盘归零来延长时间。失败只伤害生命、当前尝试或小部分进度，场地和工具仍然可用。
- 常规攻击的密度为机制让路。只有净化、护炉、双阀与逆行等允许射击的机制同时运行较慢的本体招式，其他机制主要由自身危险提供压力。

## 普通鱼、精英与探索的内容准则

已有的 108 种普通鱼不能仅以名字不同作为丰富度指标。本轮继续保留 12 类解剖轮廓、不同地区外形改造、攻击方式和精英反制；测试需检查实际行为而非只统计目录条目。

内容审查应沿下列问题逐项进行：

- 能否在第一次攻击前，从体型 / 武器部位 / 蓄力动作认出威胁？
- 同一场组合中，是否有远程压制、近身追击、区域封路、保护 / 恢复中的两种不同职责？
- 精英的机关 / 护甲是否有独立于普通鱼的反制，且避免无限弱点硬直？
- 鱼获价值是否足以解释风险，失败后是否仍有基础捕鱼的恢复路径？
- 新地点给的是一个新决定、新知识、新用途或新角色结果，还是只有旧敌人的换色？

普通物种池现在按三个钓场分布，每处每岛四种，拟饵逐步开放。首次拿起三处实际钓获样本取得一次 35 金币研究津贴；卖掉鱼不会删掉研究记录。精英系统增加或修正了半血蜕皮再生、育潮卵治疗、鳞甲正背面、墨影诱饵、弱点打断、蓄力反刺和二次追扑等反制。

内容计数应准确写为 **108 个普通物种条目 + 11 首领**。普通物种由 12 个体型家族、14 个基础攻击模板和地区变体构成；精英按 12 个体型家族共用反制模板，不是 108 套独立设计的精英 AI。本轮也没有重新制作全部岛屿地形或引入程序生成关卡。重访存在未发现物种、拟饵解锁与证物回应，不能宣传每次登岛都会生成全新的关卡。

## 金币成长与战斗手感

数值由 `EncounterTuning` 和基础武器 / 经济表集中审核。首领窗口分别调节，不统一为七秒；首领基础生命没有为拖长测试时长而再次增加。目标时长是体验参考，不是硬性测试下限。

可购买升级需要保留“当前的短板能被一次有意义的购买缓解”的感觉。基础捕鱼的收益、任务奖励、首次探索奖励、商店库存和专精解锁必须一起验算。避免某场强制机制要求已经花掉的消耗品，也避免唯一正确购买路线。

武器的命中、后坐力、换弹节奏、距离差异和命中停顿应共同服务操作反馈。枪械差异必须在实际射击循环中成立，而不是只看面板 DPS。自动化需要覆盖弹匣、空枪、换弹中切枪、失误装填、散弹距离和弱点收益；真人测试补充瞄准清晰度、鼠标疲劳和输入延迟。

## 必须运行的反例测试

1. 对 11 位首领只站桩连射：不能跳过阶段机制，但允许已设计的削甲收益。
2. 每种机制主动触发一次失败，再使用相同正常输入恢复；确认没有必须重开整场的软锁。
3. 暂停时停止倒计时和连续动作；解除暂停后继续；离开战斗清理所有物件和音源。
4. 蟹引错落点 / 命中木桩；音鳐错音 / 正确顺序；净化无水 / 持水；镜面错误 / 连链；拉钟提前 / 窗口内。
5. 热炉离远 / 失温恢复；电荷超时 / 接地；阀门过压 / 稳温；镜鲨站桩 / 实际路线；克拉肯用枪 / 错时持续收线 / 后段圈外收线不推进 / 红潮换侧和腕击回避 / 末阶段跳环；白鲸假回波 / 双环定位后未避开不计数 / 正确闪避保存 / 后两阶段不泄露正确方位。白鲸第三阶段另查：避开第一道后 `ObservationLeg` 从 0 变为 1 且观测次数不变；第二道重新锁定；第二道受击不保存本次，两道均成功只保存一次；两道间暂停不会丢失待执行回调。
6. 三阶段不是只测直接调用 `BeginPhase`：完整战斗应真实掉血跨越两条生命边界，读到所有阶段并合法击败首领。
7. 所有通关动作调用与玩家相同的 `UseAction` / `SetActionHeld` / 移动 / 装备 / 射击入口。不得调用私有 `Solve`、设置 `Active=false` 或直接删除机制对象来伪造通过。

## 实现与交付边界

实现文件：`Combat/BossMechanism.cs`、`Combat/BossMechanismArt.cs`；集成由 `EncounterDirector`、`Enemy`、`GameDirector` 和 HUD 完成。数据和叙事分别由数值、文案协作模块维护。美术 / 音乐可通过公开状态增强表现，不应改变判定或引入新的隐性通关条件。

首轮部分构建、功能测试和截图已取得，并真实暴露过两个终局首领过易、提示重复遮挡的问题；对应实现已经再次改动。旧 PASS 不自动适用于后来的代码，最新结果以 `QA-v05.md` 与逐次保留的运行目录为准。不会把机制表、脚本行数或自动化断言数量当作“正式游戏完成”的证明。
